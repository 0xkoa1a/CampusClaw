# 设计

## 课堂范围

第七课工程规则写入 AGENTS 引用的五类规则文件，沿用已有仓库和健康检查；不擅自修改 GitHub 主干保护设置。第八课仅观察安全基线，保留真实红项供后续课程，不提前执行第九、十课修复与交付。

## 数据与接口

扩展已有 assignments 表，保留旧编号与标题；新增教师、题干、参考答案、评分规程、满分及可选技能编号。学生响应不得包含参考答案和内部规程。新增 submissions、grading_tasks、grading_results 和 task_outbox。

教师 POST/GET /api/assignments，GET /api/assignments/{id}；学生 POST /api/assignments/{id}/submissions，必填 Idempotency-Key 头与 content。返回202和task_id，不在请求线程调用模型。GET /api/tasks 和 GET /api/tasks/{id}只读：学生仅自己的任务，教师可看本班任务。跨班、他人和不存在统一404；写教师资源的学生403；非法输入400；同一幂等键换正文409。

同一用户、作业、幂等键唯一；提交记录、任务与外箱在同一SQLite事务中提交。重复同内容返回原任务。任务状态 pending/running/succeeded/failed/dead，结果按submission_id唯一，任务一一对应提交。外部调用不能在数据库事务内进行。

## 队列与恢复

选择 RabbitMQ + pika，不是课程指定产品。采用 durable 队列、delivery_mode=2、发布确认、手动ACK、prefetch=1和至少一次投递。SQLite外箱跨越数据库与代理的双写边界：提交成功后，即使代理离线也可返回已持久化的202；独立worker中的调度器恢复后发布。外箱携带版本号，确认只更新本次版本，避免消费者重试覆盖新一轮待发布记录。

消费者用数据库条件更新抢占任务，记录lease_token与租约时限。运行中重复消息不重复执行；进程崩溃后，调度器回收过期租约并重新投递。结果、任务成功状态在同一事务提交后ACK。外箱确认前崩溃可重复发布，由消费端唯一约束吸收。

临时错误按指数退避加抖动重试，默认最多3次；输入、权限、停用技能和模型输出结构错误为永久失败。重试耗尽进入dead并保留原因，死信通过外箱投递到独立持久队列。LLM可能在结果落库前崩溃时被再次调用；保证结果只生效一次，不声称模型费用只发生一次。

## 模型与展示

批改提供当前题干、参考答案、评分规程和学生正文，要求JSON score/feedback，服务端校验分数范围、有限数字和反馈长度。教师内部参考信息不出现在任务查询里。测试可注入GRADING_PROVIDER；替身结果明确标为本地确定性测试。

新增 /assignments 页面，教师创建作业，学生提交后轮询任务状态，刷新可恢复列表和结果。所有动态文本用textContent，沿用既有Bearer和Cookie身份链路。

## 验证边界

先在本地验证事务、并发、去重、重试、租约与权限；真实代理不可用时必须明确跳过，不能用内存替身证明RabbitMQ持久化。真实队列与CLab验证需要VPN时再请用户连接。真人交叉评审保留待办。
