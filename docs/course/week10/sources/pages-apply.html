实践步骤与验收

这一页把四道沟的填法排成六步，按顺序走完即达到本课验收：一条命令挡得住坏提交、任何机器一键起、推送即构建、面板看得见三个技能、压测报告有前后对比、真实用户用过并留下反馈。所有支撑证据归档进仓库根目录 reports/，最终项目报告写在根目录 report.md、只写结论与指向——这些证据当场可被打开复核。

先说清几个词

这一页用到的词先在这里讲明白。

收口：把散在各处（文档、记忆、当堂操作）的判据集中成仓库内可执行的文件。本课的主动词。
验收材料：展示时能当场执行的东西——命令、面板、报告，而不是「我们做了」的叙述。最后一课的展示以这一课的归档为底。
演示环境：与真实部署同构的一份环境。从同一镜像起，配置用演示值——展示时出的问题应在演示环境先出过。
前后对比：同一脚本同一参数跑出的两轮数字。换了脚本或档位，对比即失效。
分工建议：一条流水线三段——测试收口、容器与流水线、观测与压测——正好对应三人的兼任分工，交叉验收对方的段落。

1六步实施

步骤动作产出完成判定
① 测试收口盘点各课判据；每个必做技能至少一条检查落进 apitest/cases/ 或单元测试；聚合进 make check套件与门禁命令故意改坏一处，命令退出码非 0；修回复绿（先红后绿留证）
② 容器化写 Dockerfile（多阶段）与 Compose；密钥不进镜像构建说明书与编排文件换目录按 README.md 一键启动，健康检查全过
③ 流水线自动构建配置入库：检出 → make check → make check-security → 构建镜像流水线配置与运行记录推送后自动构建通过；本地红则推送也失败
④ 观测指标按技能命名；面板三张图；告警一条写成判定面板链接与告警规则三个技能调用量与失败率各有曲线；人为失败一次告警触发
⑤ 压测与改进基线压测 → 定位 → 至少一项改进 → 复测压测报告（含前后对比）同一脚本两轮数字，改进项有归因
⑥ 真实用户轻量端（手机浏览器打开的网页版）复用接口；至少 3 名同学使用并记录反馈轻量端与反馈记录每条反馈对应一个任务条目或写明不做；新踩的坑进用例
顺序有讲究：先①后②③——门禁没立起来，流水线挡不住任何东西；先④后⑤——没有观测，压测中发生的错误都看不见；⑥放最后，真实用户要用的是已观测、已量过容量的系统。

2证据归档

全部落进仓库根目录 reports/，一条流水线每一段都留一份可复查的记录，报告 report.md 里写全路径引用。

文件内容判定
reports/gate-red-green.md先红后绿：改坏的那处、红的一屏、修复提交、绿的一屏四样齐，缺一即未完成
reports/boot-reproduce.md换目录（或换机器）启动的命令与结果无需口头补充任何步骤
reports/pipeline.md一次成功构建的编号与对应提交镜像编号能反查提交
reports/observe-alert.md面板路径、告警规则文本、一次真触发的通知三技能曲线可见
reports/bench.md压测基线与复测两轮数字、归因、改进提交同脚本同参数同档位
reports/feedback.md至少 3 人的记录与去向每条有对应条目或不做的理由
数据库变更若在本课发生（例如为索引改进改表），走三步走并记录当前处于哪一步——发布页的口径在归档里同样适用。
这些证据对应最终项目报告的六节：bench.md 与一次返工记录 → 复盘；gate-red-green.md 与部署地址、演示四步 → 门禁与演示；reports/review-0X.md → 审核记录；reports/risk-*.md（并发 / 事务 / 权限）→ 高风险三查；规则文件里的七类核查清单与 Harness 用法 → AI 用了在哪。报告本身只写结论，细节全部指向 reports/。

3面向展示的预演

最终验收要求的路径与命令这一课已经全部备齐——预演只是把它们按一条故事线串起来，并跑通当堂要演示的四步。

展示预演：五个动作 + 验收四步

五个动作：一，故意改坏并跑 make check——门禁拦住；二，一键启动演示环境；三，打开面板指出三个技能的调用量；四，走完异步链路；五，翻压测报告的前后对比。五个动作全部当场可执行，没有一处依赖「相信我说的是真的」。

其中第四步按最终验收的走查四步走全：POST /api/login 取令牌 → POST /api/tasks 返回 202 与任务标识 → GET /api/tasks/{id} 看 pending → running → succeeded 状态流转 → 换另一班账号 GET /api/knowledge/search 查别班讲义、断言返回 404（跨班一律 404，单侧过滤 + fetch-then-check）。

怎么看到：在部署环境（地址写作 https://<部署域名>/claw/，域名用占位符脱敏，汇报时给可访问的实际地址）逐条执行并记录每步返回码；任一步返回码不符即该步未通过，把对应断言补进 make check 常驻。

一句话记住：最终验收的可查材料，就是这一课攒下的证据——报告 report.md 写结论，证据全部指向仓库根目录 reports/。
