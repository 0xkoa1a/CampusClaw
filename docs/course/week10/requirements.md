# 第 10 课要求：测试、交付与运行验证

依据 2026-11-16 直连课程站点抓取的任务清单、教程概览和全部可访问教程子页整理。原始 HTML、URL 与 SHA-256 见 [sources/manifest.md](sources/manifest.md)。任务页将本课标为“小组任务”；课程没有给出个人独立验收线。个人可承担其负责的测试、容器/流水线、观测/压测等一段，并提交可复核证据；团队验收依赖共享 CI、部署环境、多人反馈和交叉评审。

## 小组强制要求

### 测试和门禁

- 盘点可重复运行命令（包括 `make check`、`make check-security` 和异步三条判据），记录最近执行时间；建立规约场景到用例的可追溯矩阵，每个场景至少一条用例。
- 四个必做技能各有行为检查：解题引导不泄露最终答案；教师改分优先；错题讲解不整段复述标准答案；知识库跨班检索返回 404。
- 接口和单元用例聚合到 `make check`；安全反例由 `make check-security` 执行。两条命令并列进入 CI，非零退出阻止合并。涉及模型等待时可用测试替身缩短执行时间。
- 必须故意改坏一处，证明门禁报红；修复后复绿。`reports/gate-red-green.md` 要含改坏位置、红屏及退出码、修复提交编号、绿屏及退出码 0，并可当场复跑。
- 主干 `main` 开启保护。流程为 AI 初稿、自审、脚本门禁、人工确认、交叉评审、合入；机器不可判定的需求意图由人工确认并补用例或规则。

### 容器、构建与发布

- 多阶段 Dockerfile 分离构建和运行，最终镜像不含源码、构建工具或密钥；环境值运行时通过环境变量注入。
- Compose 编排应用、MySQL、Qdrant 三服务及健康检查。应用等数据库就绪后启动，不靠等待循环。换目录（最好换机器）按 README 一条命令启动并全部就绪，归档到 `reports/boot-reproduce.md`。
- CI 配置入库：检出 → `make check` → `make check-security` → 构建镜像。推送后记录构建编号和对应提交；镜像编号须能反查提交，归档到 `reports/pipeline.md`。本地红的提交不得通过流水线发布。
- 发布前检查就绪探针；数据库变更按 expand → migrate → contract。若本课改表，先做扩与迁，删除旧结构须确认无回退需求，并记录当前阶段。

### 观测与告警

- 复用第 9 课审计七列口径。指标如 `skill_invocations_total{skill="…",status="ok|error"}`；耗时可用 `skill_invocation_seconds_bucket`。维度限于 `skill` 与 `status`，避免按用户造成高基数。失败率由错误数/总数在面板计算，不另上报重复指标。
- 面板至少三张图：三个技能分线的调用量；每技能错误率；接口 P95 与任务队列深度并排。图表支持从当天缩放至最近一小时。
- 至少一条可判定告警，写清观察量、持续条件、动作。课程示例：某技能错误率连续 5 分钟高于 1% → 通知负责人并附面板链接。必须人为制造连续失败，实际触发并送达，证据归档 `reports/observe-alert.md`。
- 指标、日志、追踪三支柱共用技能标识、请求标识、状态和耗时；请求标识贯穿网关、应用和模型调用。

### 轻量端、真实使用与压测

- 提供手机浏览器可用的 H5，复用现有接口和认证；服务端配置必要 CORS。手机端完成四步走查：登录取令牌 → 提交返回 202 与任务标识 → 轮询 `pending → running → succeeded` → 换班查别班讲义得到 404，并能在审计日志七列中查到该经历。
- 至少 3 名使用者实际使用，每人一条反馈写入 `reports/feedback.md`，含会话标识、接口、观察返回、期望与差异。每条反馈对应任务清单条目或说明不做原因；新问题加入测试套件。
- k6 脚本入库、参数走环境变量。教程示例基准为 `vus=20`、`duration='60s'`。分别对提交、查询、检索接口加压，观察多个并发档位下吞吐与 P95，标出饱和点；提交测接收能力，批改吞吐按消费者数量另行测量。
- 至少完成一项缓存或索引改进；同一脚本、同一参数、同一档位复测。`reports/bench.md` 记录两轮吞吐、P95、错误率、错误/瓶颈归因、饱和点、改进提交编号及原始数据。教程允许调并发配置作为改进思路，但任务清单验收明确举例为缓存或索引，满足验收时优先采用缓存或索引。

### 规则、风险和最终验收

- Harness 可读取的 `AGENTS.md` 与 `.cursor/rules/` 写明 AI 代码核查规则，覆盖接口入口、业务逻辑、数据库、公共函数、错误处理、安全、性能七类；逐类注明 AI 自审、脚本或人工确认手段。
- 根 `reports/` 至少归档：`gate-red-green.md`、`boot-reproduce.md`、`pipeline.md`、`observe-alert.md`、`bench.md`、`feedback.md`；另有至少 3 份 `review-01.md` 起的审核记录及 `risk-concurrency.md`、`risk-transaction.md`、`risk-authz.md`。每份审核记录写“手段 / 检查内容 / 判据 / 结果”，至少两份来自 AI 自审或脚本门禁。
- 组内另一人从换目录启动开始，独立走完最终四步演示；返回码不符记为展示前待修。运行中发现问题回到代码提交和流水线重走，不在运行容器里手改。
- 根 `report.md` 只写结论和证据路径，作为最终验收材料入口；课程证据需能当场打开复核。

## 个人课堂适用项与建议

- 每位成员应能复跑并解释本人负责部分的判据，保存本人执行命令、结果和证据；任务页未规定每人都必须独立搭完整 CI、观测系统或招募 3 名使用者。
- “测试收口 / 容器与流水线 / 观测与压测”是任务页给出的建议分工；交叉验收对方工作也是团队协作方式。三名使用者、主干保护、部署告警和同伴独立验收均按小组交付计，不应拆写成每位成员单独的数量指标。

## 验收参数速查

| 项目 | 明确判据 |
| --- | --- |
| 先红后绿 | `make check` 报非零，再修复至 0；报告含红屏、修复提交、绿屏 |
| 容器复现 | 换目录一条命令；应用、MySQL、Qdrant 健康 |
| 面板 | 三技能调用量、每技能错误率、接口 P95 + 队列深度；时间轴可缩放 |
| 告警 | 示例阈值：每技能错误率连续 5 分钟 >1%；实际触发并收到通知 |
| 压测 | k6 示例 `vus=20`、60 秒；提交/查询/检索分测并找饱和点 |
| 压测对比 | 同脚本、同参数、同档位；吞吐、P95、错误率及至少一项缓存/索引改进 |
| 真实用户 | 至少 3 人；逐条反馈有任务去向或不做理由 |

> 来源边界：上述是课程任务要求，不代表本仓库已实现、通过或已部署。根目录报告、业务代码、CI 与环境不在本次文档归档范围内。
