# 第 6 课要求与实现参考

## 阅读说明

本课在第 5 课已有的智能体、技能、知识库和流式会话基础上接入 MCP 工具。交付分在两端：一个暴露工具的 HTTP 服务，以及 CampusClaw 宿主侧的登记、发现、调用编排和记录。

以下区分课程任务清单明确列出的必做项、教程中的明确验收口径、教程建议与示例。任务清单第五节标为“接口测试（建议）”；实践页虽给出同伴交叉验证方案，本文件不把它扩写成新增验收门槛。原型与公开 OpenAPI 描述只反映课程演示系统，不自动构成必须照搬的实现细节。

## 明确的技术选型

| 项目 | 课程给出的口径 | 分类 |
| --- | --- | --- |

| 运行方式 | MCP 服务和 API 通过 `docker-compose.yml` 同网互通并一并启动 | 任务清单硬性要求 |

| MCP 能力与传输 | 本课只实现 tools 能力；教程明确本课采用 HTTP。教程解释 HTTP（Streamable HTTP）和 stdio 两类传输，但本课范围收敛为 HTTP | 任务清单与教程明确要求 |
| 鉴权 | MCP 服务使用 Bearer 令牌；令牌从环境变量读取。主机侧把令牌保存在服务端，调用时放入 `Authorization` 请求头 | 任务清单硬性要求 |

因此，关于“强制技术选型”的结论是：MCP、同仓 Compose 部署、HTTP JSON-RPC 2.0 的 `/mcp` 端点和 Bearer 鉴权是本课明确边界；LangChain、框架、SDK、通用 Skill 文件标准均未指定。MCP 传输并非任意：课件比较 HTTP 与 stdio，但本课明确选择 HTTP。

## 课程任务清单中的硬性要求

### 自建 MCP 服务

- 在本课仓库内新增 `mcp-server/`，与主应用同仓，由 Compose 一并构建和启动。
- 提供 `POST /mcp`（JSON-RPC 2.0）与 `/health`。
- Bearer 令牌来自环境变量（任务清单举例 `MCP_AUTH_TOKEN`），不得进入 Git、镜像层或前端。
- 实现 `initialize`、`tools/list`、`tools/call`。无令牌或错误令牌返回 401；非法请求返回可读 JSON-RPC 错误。
- 至少实现两个可调用工具。工具名符合宿主引用规则；工具能被 `tools/list` 发现，并由 `tools/call` 返回文本结果。
- Compose 中 MCP 服务与 API 可互通；主应用以 Base URL（示例 `http://mcp-demo:8090`）连接真实自建服务，不只 mock 宿主逻辑。

### 宿主侧登记与发现

- 教师可登记本班 MCP 服务器名称与 Base URL。Bearer 令牌只保存在 CampusClaw 服务端；接口响应不得返回密钥。
- 教师可连接服务器：完成握手并调用 `tools/list`，把清单缓存到本系统。
- 断开服务器后清空缓存，后续不可调用。
- 连接失败时提供明确错误提示，不阻断第 5 课已有的检索与流式对话主路径。教程对失败后的状态有内部矛盾：连接流程图与表格写明置回“未连接”并清空发现清单，第一张图的图注却说连接状态和清单不更新。本文按流程图与表格中明确写出的处置记录为置未连接、清空缓存。
- 登记的 Base URL 指向 Compose 中自建服务；连接后管理界面能看到实际实现的工具名。

### 技能绑定与鉴权调用

- 技能文件的“工具”除 `knowledge_search` 外，还支持 `工具名@服务器名`，例如 `formula_hint@campus-tools`。
- 保存技能时校验 MCP 工具属于本班、所在服务器已连接，并且工具已出现在发现缓存中；不满足时拒绝保存。
- 学生提问命中带 MCP 工具的技能后，服务端携带令牌调用远端 `tools/call`。
- 工具结果以 `tool` 角色消息追加到模型的 `messages`，作为数据位内容而非系统指令；按教程对工具消息角色的定义，不要求再复制为 `user` 角色消息。
- 流式响应的 `meta` 中在有工具调用时包含 `tool_calls`（工具引用与状态）。未连接或越权调用标为 `denied`，不得静默成功。
- 继续遵守第 3–5 课权限边界：班级来自会话；跨班资源与不存在资源按一致 404；使用 Bearer 鉴权。

### 审计与接口文档

- 教师可以查看本班 MCP 工具调用审计，至少包含 `tool@server`、状态、用户和时间。
- 为 MCP 相关接口补充 OpenAPI 注解并生成文档。Swagger 可打开并试调连接、工具列表、技能保存等主要接口。
- 任务清单的公开 Swagger/OpenAPI 还列出登记、修改、删除服务器、连接、断开、查看发现工具和查看调用审计等接口；这些名称用于阅读课程原型，不等同于新增的路径命名规范。

公开 Swagger 中 MCP 分组当前列出以下原型路由，便于对照页面和接口文档：

| 方法与路径 | 原型用途 |
| --- | --- |
| `GET /api/mcp/servers` | 列出本班 MCP 服务器 |
| `POST /api/mcp/servers` | 登记 MCP 服务器 |
| `PUT /api/mcp/servers/{id}` | 修改服务器 |
| `DELETE /api/mcp/servers/{id}` | 删除服务器 |
| `POST /api/mcp/servers/{id}/connect` | 连接并发现工具 |
| `POST /api/mcp/servers/{id}/disconnect` | 断开服务器 |
| `GET /api/mcp/servers/{id}/tools` | 查看已发现工具 |
| `GET /api/mcp/tool-calls` | 查看 MCP 工具调用审计 |

这些是课程原型中可见的路径，不是要求所有实现照搬的接口命名。

## 教程给出的验收口径

### 服务和连接

- 带正确令牌可发现自建工具并调用得到文本；错误令牌被拒。
- 登记响应只暴露“是否已配置令牌”布尔信息，不回显令牌。
- 连接成功展示工具清单；地址或令牌错误时连接失败并给出可读原因。教程内部表述不一致：连接流程图和步骤表明确失败后置为未连接并清空清单，第一张图的图注则称连接状态与清单不更新。此处依据明确的流程图和步骤表，记录为置未连接、清空缓存。
- 每次成功连接以本次发现清单整体替换旧清单，不追加。
- 断开后清空清单；引用其工具的技能不能再成功调用。

### 引用、调用与循环

- 保存技能时拒绝格式错误、未登记、未连接或不在最近发现清单中的 MCP 工具引用，并返回可读错误。
- 候选工具先按当前用途划定子集，再由模型在子集内选择；工具声明来自发现结果，名称、说明和输入结构保持一致。
- 宿主按照工具输入结构校验模型参数，通过后才带令牌调用；模型和前端均不接触 MCP 地址或令牌。
- 一次提问可以连续调用多轮；必须有轮次上限及累计调用次数/时间上限。触顶停止调用，让模型用已有信息作答，不以错误终止对话。
- 工具失败作为包含原因的 `tool` 角色消息返回模型，允许模型选择后续策略；无需另行复制为 `user` 角色消息。工具失败本身不应中断检索与生成主路径。
- 调用事件先于正文到达。多轮时按发生顺序发送；仅在有调用时提供 `tool_calls`。

### 安全与信任边界

- 工具说明和工具返回都会进入模型上下文，均按不可信输入处理；检索材料位于 `user` 消息数据位，工具返回以 `tool` 角色消息进入数据位，两者都不进入系统提示。
- 工具结果在进入上下文前按教程建议做指令式句式检查；命中时整条丢弃并换成固定说明。教程同时明确这只是软防线，不能视为完备过滤。
- 宿主执行逐工具授权、参数校验和配额；模型只提出调用，不授予自己执行权。
- 令牌只存于服务端，并在发起请求时用于 Bearer 请求头。接口响应、前端回显、日志和容器镜像不得暴露令牌原文；每台服务器应单独使用令牌。
- 教程建议写操作和外发操作要求人工确认、工具说明变化后重新确认。这些安全建议应结合当前工具副作用设计；本课验收页没有规定特定确认界面的技术实现。

### 调用记录和管理界面

- 每次可归属到服务器的调用至少记录工具引用、服务器、结果状态、触发用户、所在会话、轮次和时间；成功记录结果摘要，失败记录原因。
- 管理页可登记和维护服务器名称、地址、是否配置令牌；查看连接状态与失败原因、已发现工具及参数、最近调用记录。
- 教师之外的角色不能使用管理能力；授权在服务端判定。访问别人的服务器标识时，响应应与访问不存在标识一致。
- 本课要求落在日志层；指标和分布式追踪在教程中列为后续扩展，不是本课交付。

## 教程建议、示例与非要求

- `formula_hint`、`unit_convert` 是任务清单示例；可以换成贴合班级场景的工具，但仍须满足两项可调用工具和文本结果要求。
- `MCP_AUTH_TOKEN`、Base URL `http://mcp-demo:8090`、`formula_hint@campus-tools` 是示例值，不是必须使用的固定名称或密钥。
- 教程介绍 stdio 和 HTTP（Streamable HTTP）两种传输，讨论 SSE；本课任务选择 HTTP，但未要求必须用某个 MCP SDK 或实现所有 MCP 能力。
- 教程讨论一种完整 MCP 结构与课程教学子集的区别：复现方法名和报文形状本身不等于完整实现。本课具体实现边界仍以任务清单写明的 `POST /mcp`、三个方法、工具能力为准。
- 多工具候选集、配置期引用校验、运行期连接状态检查、调用事件顺序与轮次限制属于教程说明并与验收点相互印证；教程提出的输出侧外发意图扫描属于后续课程范围。
- 同伴交叉验证页列出服务器隔离、令牌不回传、断开即失效、调用记录可见范围四个检查方向。归档保留此来源信息，但不将同伴验收设为本课额外硬门槛。
- 第 5 课的 `knowledge_search` 保持为内置工具项，不需要绑定 MCP 服务器。

## 任务清单中的建议测试与证据

任务清单将“接口测试”明确标为建议：可以为登记、连接、列出工具、断开增加 `apitest/` 用例，并验证非教师返回 403；可以串起“连接示范 MCP → 注册工具技能 → 会话提问 → 审计出现 ok 记录”，并用 `run_all.py` 生成 HTML 报告（报告不提交 Git）。这些是建议测试路径，不应改写成任务清单的硬性验收项。

任务清单自查建议覆盖：单测 MCP `/health` 与 Bearer 工具调用；验证宿主连接、发现、绑定、对话触发和审计；验证断开后调用被拒；确认两侧令牌一致且未进入前端、Git 或镜像。

## 不确定处与边界

- 首页将第 7、8 课标为“课件待补充”，所以截至 2026-10-21 最新可用课为第 6 课；页面没有提供本课发布时间或截止日期，本目录不猜测。

- OpenAPI 和 Swagger 展示 CampusClaw 原型的完整现有 API。它们可帮助辨认管理接口，但不能据其所有路径推断为本课新增工作。
- 根目录 `AGENTS.md` 的 OpenSpec 流程属于仓库规则：实现前先写并 Review 可验收规约。它与本文件中标注的课程网页要求分开。
