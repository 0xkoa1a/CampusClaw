# 第 6 课任务清单提取

来源：[第 6 课任务清单](https://devops.hello1023.com/课程任务清单-第6课.html)。逐项阅读页面中的六个部分；以下按原清单结构提取，任务内容的结构化归纳与硬性/建议分类见 [requirements.md](../requirements.md)。

## 清单结构

- 一、自建 MCP 服务器（`mcp-server/`）：在现有仓库同仓新建；Compose 启动；`POST /mcp` 使用 JSON-RPC 2.0；提供 `/health`；Bearer 环境变量；`initialize`、`tools/list`、`tools/call`；至少两个工具；服务与 API 同网；正文提及示范工程 `project-src/week06-harness/mcp-server/`。
- 二、主机侧登记与工具发现：教师登记本班服务器；服务端保存令牌；连接执行握手与工具发现并缓存；断开清缓存；失败可读且不影响第 5 课主路径；连接实际自建服务。
- 三、技能绑定与鉴权调用：技能工具项支持 `knowledge_search` 和 `工具名@服务器名`；保存时校验班级、连接状态和发现清单；服务端带令牌调用；工具结果是数据；`meta.tool_calls` 显示引用与状态；沿用既有身份与班级边界。
- 四、审计与 Swagger：教师查看至少含工具引用、状态、用户、时间的审计；补 MCP OpenAPI 注解；Swagger 能试调连接、工具、技能保存等主要接口。
- 五、接口测试（建议）：为登记、连接、列工具、断开和非教师 403 增加用例；给出端到端用例建议；`run_all.py` 生成 HTML 报告且报告不提交 Git。
- 六、验收证据（自查）：分别检查服务健康与工具调用、宿主连接发现绑定触发审计、断开后拒绝，以及令牌只在本机环境变量且未进入前端/Git/镜像。

清单最后说明：在第 5 课仓库增量实现，主应用仍为一个 CampusClaw，另加同仓 `mcp-server/`；以第 6 课课件为准，密钥放本机 `.env`。

清单中“接口测试”明确标注为建议；自查项是实现者核对路径。教程页另外提出同伴交叉验证，但本目录不把它增列为正式验收门槛。
