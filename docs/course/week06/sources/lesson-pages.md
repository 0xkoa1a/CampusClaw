## 概览

[实现教程概览](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/index.html)

课程把工具接入分为服务器端与宿主编排两端。教程强调能力、传输、报文三层分开；工具发现提供模型工具声明；模型决策、宿主负责执行和收尾。风险新增为工具说明和返回内容可能进入提示词；令牌留在服务端。

## 预习：工具调用要解决什么

[页面原文](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/pages/preview.html)

页面从时效知识、精确计算和访问外部系统三类模型限制引出工具调用。区分 RAG 提供事实与工具调用执行动作；说明 MCP 是 Host 与工具服务器之间的开放协议，模型不直接发 MCP 报文；比较函数调用、厂商插件、OpenAPI 加函数定义和智能体框架工具抽象。教学交付要求两端都存在：实现协议的服务器和宿主中的调用循环。

## 本课重点

[页面原文](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/pages/scope.html)

六个知识点为协议分层、工具声明、候选集与最小权限、调用循环、信任边界、可观测性。两端交付包含 MCP 服务（握手、列工具、执行工具、至少两个工具、令牌校验）和宿主登记发现、工具声明、参数校验、调用结果回传与循环控制。验收检查覆盖令牌不回传、发现、断开后拒绝、保存前引用校验、模型调用和宿主校验、循环上限与调用记录。

## 协议的三层

[页面原文](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/pages/mcp-model.html)

页面解释 tools、resources、prompts 三种能力；介绍 stdio 与 HTTP（Streamable HTTP）传输，以及 JSON-RPC 2.0 的请求和响应形状。握手 `initialize` 协商版本与能力，`tools/list` 发现工具，`tools/call` 执行工具。本课范围明确限定为 tools 能力和 HTTP 传输，服务端实现上述三个方法并校验令牌。发现结果是快照，服务器端变化会导致旧引用失效。

## 工具声明与候选集

[页面原文](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/pages/binding.html)

工具声明由发现结果产生，包含名称、说明和 `inputSchema`；返回为内容数组并带错误标记。说明应写清适用与禁用场景、边界和参数范围。宿主先依据任务或角色限制候选工具，再将候选声明发给模型。引用格式是 `工具名@服务器名`；配置时检查格式、存在、连接状态及工具是否在最近发现清单中，调用时仍检查当前连接状态。内置 `knowledge_search` 不需服务器。教程给出合法/非法引用和工具名格式示例。

## 调用循环

[页面原文](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/pages/bridge.html)

连接时读取登记信息、握手、发现工具、整体替换旧清单并标记已连接。失败后的状态表述存在内部矛盾：流程图和步骤表写明置回未连接并清空清单，第一张图的图注却说连接状态和清单不更新；requirements 按流程图和表格的明确处置记录为置未连接、清空缓存。每轮提问由宿主发送提问与候选工具声明，模型给结构化工具调用，宿主按结构校验并携带令牌执行，再以 `tool` 角色消息将结果作为数据位内容交回模型。通过模型停止请求、轮次上限、累计调用次数或时间上限终止循环；超限后停止调用并基于已有信息作答。工具失败应作为带原因的工具消息回传，不静默丢弃，也不终止检索生成主路。

## 工具带来的风险面

[页面原文](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/pages/security.html)

工具返回与检索材料一样不可信并进入数据位：检索材料在 `user` 消息一侧，工具返回以 `tool` 角色消息进入 `messages`，均不进入系统提示。教程建议在进入上下文前过滤已知指令式句式，并明确这不能消灭提示注入。工具说明也会原样进入提示词，可能遭工具投毒或事后变更。宿主需处理逐工具授权、读写区分、配额；写操作及外发操作的人工确认是教程安全设计建议。令牌只在服务端存储和出站 Authorization 请求中出现；接口响应、前端回显、日志不能出现明文；每台服务器分别使用令牌。

## 调用的可观测性

[页面原文](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/pages/audit.html)

调用记录回答动作、结果、用户、会话/轮次、时间五类问题；成功留结果摘要，失败留原因。流式 `meta` 事件须先于正文，并在实际有调用时带 `tool_calls`。管理界面查看服务器信息、令牌配置状态、连接状态和失败原因、发现工具与参数，以及最近调用记录。教师以外角色的权限在服务端判定。课程本阶段做调用日志，指标和追踪属于后续扩展。

## 实践步骤与验收

[页面原文](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/pages/apply.html)

教程推荐按工具服务、登记存储、连接发现、调用循环、界面与可观测性的依赖顺序推进。给出故障定位表，覆盖连接失败、引用保存失败、未触发调用、循环不收敛、被拒、结果未体现和找不到记录等情况。页末列出四项同伴交叉验证及证据建议；本目录保留其为教程验证建议，不新增验收门槛。

## 思考与分析

[页面原文](https://devops.hello1023.com/课件/第6课-课件-MCP与工具接入/pages/think.html)

五题分别讨论协议结构与传输、校验时机、调用决策归模型还是代码、工具返回和检索资料为何走数据通道、工具说明是否可信。页面对比 stdio、HTTP、SDK、模型驱动和代码驱动等方案；这些是研讨用替代方案，不是任务要求采用的技术。页面也指出本课按方法名和报文形状实现的教学服务不等于完整 MCP 实现。
