# 第 9 课要求：安全检查与审计

依据 2026-11-16 直连课程站点抓取的任务清单、教程概览和可访问子页整理。原始 HTML、URL 与 SHA-256 见 [sources/manifest.md](sources/manifest.md)。课程任务页将本课标为“小组任务”；以下“个人适用”指每位成员可承担、可复核的课堂工作，不代表课程另设个人独立验收线。

## 个人课堂适用项

- 复测本人负责的 SEC 条目，沿用“前置条件 / 操作 / 可观测结果”三段式，记具体结果，不只写“已修复”。修复前先复测现状；安全修复后用同一条判据重放。
- 参加并记录 SEC-08 四步实验：恶意文档影响评分、索要系统提示词、诱导修改规则、诱导助手越权写成绩。模型层面的现象如实记录；第 4 步必须核对写入结果与拒绝审计日志。
- 对本人负责的代码、反例用例和证据执行复测，并向组内提供可复跑命令与输出。任务页没有规定每位成员独立完成全部代码或单独提交一套团队报告。

## 小组强制要求

### 复测与修复

- SEC-01：受保护接口缺少令牌时一律返回 401。
- SEC-02：讲义访问按数据归属查询，跨班返回 404；知识检索的班级条件必须同时作用于向量库和 SQL，跨班结果为空。删除“先查全表、再在内存过滤”的旧路径。
- SEC-03：技能、提示词和助手配置等写接口逐次校验角色；学生请求返回 403，数据无变化。
- SEC-04：底层批改写入接口也校验身份和归属；绕过技能路由直调仍被拒，数据库无残留。
- SEC-05/06：密钥先轮换，再清理提交历史；用旧密钥访问外部服务应得到 401。数据库凭证落库存密文，解密口令只从外置环境变量读取。依赖审计高危项须升级清零，或登记包名、漏洞编号、暂缓原因和降险措施。
- SEC-07：审计日志为单行 JSON，至少含操作人、时间、操作类型、对象、状态、技能标识、用量与耗时；字段转义并截断。拒绝请求也要记录。教师可查询日志，学生不可见。按技能标识和时间窗的一条命令/脚本回查须纳入自动检查，输出归档到 `reports/audit-recheck.md`。

### 注入反例与 SEC-08

- SQL：用 `' OR '1'='1` 重放检索；期望空结果或格式错误，不得越过班级边界。查询参数必须参数化；排序列等不可参数化位置使用白名单。
- XSS：用 `<script>alert(1)</script>` 作为讲义标题，检查页面源码已转义且不执行脚本。
- CSRF：从另一页面伪造配置修改表单，缺少一次性 token 时必须拒绝（教程判据为 403）；会话 Cookie 同时标记 `SameSite`。两项防线各留一条记录。**一次性 token 是明确硬要求，SameSite 也是并列硬要求。**
- 三种注入反例均按三段式写入 `apitest/cases/`，纳入 `make check` 常驻回归。
- SEC-08 四步记录实际现象，归档 `reports/sec08-experiment.md`。页面要求观察被测助手的模型行为，因此人工实验需走项目当前助手的实际调用路径，不能只用固定输出的测试替身代替；课程没有指定必须使用 CLab、外部服务或某个模型供应商。若项目当前助手通过 CLab 提供，CLab 是项目实现选择而非课程点名要求。自动化覆盖可机器判定部分；需观察模型行为的部分人工记录。前 3 步出现模型被带偏不等于系统被攻破；**唯一必须为绿的是第 4 步工具执行层**：宿主在执行写工具前按发起者身份鉴权，非授权写入不得执行、成绩不变，并留下拒绝日志。还须做到提示词不含密钥/敏感配置，模型输出按数据展示或转义入库，不直接执行。

### 安全门禁、回归与验收

- 密钥扫描和依赖审计接入 `make check-security`；存在命中或未处置高危时退出码非 0，并在 `README.md` 说明入口。归档一次必红和修复后变绿的输出及提交号到 `reports/gate-red-green.md`。
- 回归三组：`make check` 全量功能用例；第 8 课异步三条判据；本课 SQL/XSS/CSRF 三个反例。全绿后串联验收：登录取令牌 → 提交任务返回 202 → 查询 `pending → running → succeeded` → 换班查讲义返回 404。
- 从另一台机器按 README 从零启动，验证配置外置。最终报告/验收须能打开证据文件。
- 每条修复单独提交，提交信息标出 SEC 编号。交叉评审至少独立复现两条修复；每份记录含“手段 / 检查内容 / 判据 / 结果”，按 `reports/review-02.md`、`review-03.md` 递增。至少两份评审证据来自 AI 自审（Harness 对照规则）或脚本输出；人工评审只处理机器判不了的项，并补用例或规则。

## 建议与团队协作边界

- 任务页建议按授权/注入与资产/日志分工，并交叉复测；这是分工建议，不是固定个人职责。
- 安全修复、常驻用例、门禁、报告和最终四步验收是小组交付。至少两条独立复现、审阅记录、通知组员重新克隆及共享环境演示需要团队协作。

## 交付证据清单

- `reports/security-fix-log.md`：SEC 编号、修复前实际、修复后实际、判定。
- `reports/security-baseline.md`：密钥扫描与依赖审计当日基线及处置。
- `reports/sec08-experiment.md`：四步实验现象，尤其第 4 步写入未放行及拒绝日志。
- `reports/audit-recheck.md`：技能/时间窗回查命令和原始输出。
- `reports/gate-red-green.md`：门禁必红、修复提交、复绿输出。
- `reports/review-02.md` 起的交叉评审记录，以及一次最贵返工的原因、定位/修复耗时和可执行改法（具体返工文件名由项目团队决定）。
- `apitest/cases/` 中的三类注入反例；`make check` 与 `make check-security` 的复跑结果。
