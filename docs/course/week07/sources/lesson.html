小组项目启动

本课启动小组学期项目，四步一次做完：建仓库 → 定规约 → 立规范 → 落骨架。四步的产出各不相同，作用却是一致——让后续课次都能在同一个仓库上、按同一份规约增量交付，而不是每一课重新对齐一遍做法。立规范这一步要产出五类规范的文件：产品设计、后端开发、安全开发、测试、部署运维，课件里每类各有一页明细。仓库是协作与回溯的载体，规约是验收标准，规范是生成的约束，骨架是每课验收的基线。

词先说清几个词

小组项目本课含义本学期以小组为单位交付的学期项目；仓库、规约、规范与骨架都为它而设。
规约本课含义一份变更的四份文件：动因、设计、需求规约、任务清单。既是给 Harness 的指令，也是验收时逐条对照的表。
规范本课含义某一类工作要写清什么、为什么、怎么检查的条目清单，分五类必修加三类补充。
规则本课含义落在 Harness 规则目录里的常驻约束，每次改代码都会被读到。
技能本课含义按场景调用的流程文件，需要时被加载执行。
骨架本课含义一条命令可启动、健康检查返回成功的最小实现，后续课次的验收基线。

1本课要交付的四步

四步里只有最后一步产出代码；前三步产出的载体、标准与约束，决定这份代码在反复修改后仍能保持一致。

步骤产出完成后的可验证点在哪一页
建仓库仓库、README、忽略规则、协作约定每人克隆（clone）后按 README 跑通一次；主干随时可启动建仓库与协作约定
定规约一份变更的四份文件与场景清单校验命令通过；另起一次会话只给出仓库路径与变更名，Harness 能照做定边界与规约
立规范规则文件，以及按需调用的技能修改一次代码，生成产物的分层与命名符合规范；另起一次会话结果仍一致工程规范写进规则与技能
落骨架可启动的最小实现、健康检查端点、版本标签克隆 → 填入配置 → 一条命令 → 健康检查端点返回成功，四步无需人工补充说明骨架与核查清单
顺序不是形式要求：前三步各产出一个后面要反复引用的东西——提交历史、场景清单、同一份约束——第四步才有可验证的基线。

2先记住三条结论

规范要落在 Harness 读得到的地方

常驻约束写成规则文件，每次改代码都会被读到；按场景执行的流程写成技能，需要时调用。写在会话里的规范，会话结束即失效，更换成员或更换机器即回到各自的编码习惯——规范只有落在规则文件与技能里，才谈得上持续生效。

规约先于代码，且要判定得出来

每条能力先写成场景：前置条件、操作、可观测结果，再交给 Harness 实现。规约既是给 Harness 的指令，也是验收时逐条对照的表。先写代码后补规约，判定是否完成缺乏客观依据。

骨架是验收基线，不是业务代码

骨架只做一件事：一条命令可启动、健康检查端点返回成功、配置全部外置。它不含任何业务，却是后续课次的起点——没有这条基线，出了问题是骨架缺陷还是当次新增功能的缺陷，无从判定。
