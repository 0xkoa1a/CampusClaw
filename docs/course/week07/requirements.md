# 第 7 课要求：个人课堂工程适用部分

## 归档范围

第 7 课任务页以小组学期项目启动为目标，要求组长建仓库、邀请成员、设置主干保护，并由成员协作完成规约、规范和骨架。本归档面向现有个人课堂工程，只采用可直接用于个人开发的工程要求；小组分工、成员邀请、组内交叉评审和新建小组仓库不构成本人的本课工作。

## 个人工程基线

### 规约先于实现

每项变更先明确用户、要解决的问题、交付能力及本次不做的范围。规约包含动因与边界、设计与取舍、需求场景、可执行任务清单。每个需求用前置条件、操作和可观测结果描述；失败路径覆盖参数非法、无权限、资源不存在和依赖不可达。验收标准写出具体值或可判断条件。

### 规范放在工具每次都能读取的位置

常驻约束写入仓库级规则文件；需要按特定流程执行的工作写成技能。两类文件都写明检查方法。课程列出的五类基础规范为产品设计、后端开发、安全开发、测试、部署运维；AI 应用、数据、评审与完成定义规范可按项目需要补充。

个人工程可据此明确：页面与状态、接口分层和错误响应、服务端授权与密钥管理、测试组织与通过判定、环境配置与日志、AI 调用边界和数据留存等要求。规范的验收重点是能否检查，而非文件篇幅。

### 骨架保持可启动、可判错

骨架只提供符合分层约定的最小应用入口，不提前生成完整业务实现。配置从环境读取，提供免认证的 `/health`，日志按一行一条 JSON 输出并带请求标识。按 README 从克隆、配置到单命令启动，健康检查应能成功；缺少必需配置时应明确失败。

### 变更记录便于复核

每项变更关联其规约和验收记录。实现中的设计或任务调整同步回规约。课程要求团队仓库保存规范、运行说明和验证证据；个人工程可保留同等可追溯材料。密钥只放在本机环境配置，不进入代码、镜像、前端产物或版本历史。

## 课程验收口径与个人适用性

| 课程内容 | 课程原文口径 | 个人工程采用方式 |
| --- | --- | --- |
| 项目价值和范围 | 说明目标用户、问题、价值差异；列能力和排除项 | 每项个人变更写清目标与范围 |
| 规约 | 四份文件；需求以场景表达；严格校验并检查需求到场景的映射 | 保留完整、可判定的变更规约 |
| 规范 | 五类基础规范落在 Harness 可读取的规则与技能中；按条目给检查法 | 维护个人仓库的通用规则和场景流程 |
| 骨架 | 单命令启动，`/health` 成功，配置外置，结构化日志 | 作为新工程或重构后的启动基线 |
| 小组协作 | 成员加入、保护主干、组内独立启动和交叉评审 | 不适用为个人任务；可采用 README 可复现原则 |
| 提交与标签 | 归档变更并打骨架标签 | 课程团队流程要求；本归档仅记录，不替当前任务创建标签 |

## 来源边界

本文件把任务清单的规范要求概括为个人工程实践建议，并标明了不可直接迁移的小组协作项。关于本仓库既有规则的遵循情况，不由课程网页替代判断；具体实现仍按仓库自己的 `AGENTS.md` 约束执行。
