# 产品设计规范

## 当前产品边界

- 主要用户是班级教师与学生；教师维护本班材料、智能体和工具，学生使用本班资源学习。身份与班级由服务端会话确定。
- 现有入口包括登录、资料、会话和 MCP 管理。第 8 课作业管理与批改按异步 OpenSpec 验收；源码或页面文件存在不等于功能已部署，状态以实际验证记录为准。
- 当前不扩展家长端、多校区运营或学科交易市场；当前课堂交付范围见本目录 README。

## 页面与流程

- 新增作业页按角色展示：教师创建和查看本班作业；学生查看可提交作业、提交正文、查询自己的任务和结果。学生页面不得展示参考答案、评分规程或他人提交。
- 页面加载数据时显示加载状态；有数据时显示正常状态；零条数据时说明如何开始；请求失败时显示可恢复的错误。四种视图状态各有独立文案，不以空白页面表示加载或错误。
- 异步作业状态按 `pending`、`running`、`succeeded`、`failed`、`dead` 显示可理解的中文。任务标识可用于刷新后继续查询；轮询遇到终态后停止。
- 表单在提交前提示必填项、长度和数值范围；服务端再次验证并返回可定位的字段错误。客户端检查只改善体验，不作为数据有效或授权的依据。
- 提交按钮在请求处理中禁用；重复点击沿用同一个幂等键。网络超时后页面允许查询原任务，不能悄悄生成新提交。

## 文案与验收

- 固定使用“作业”“提交”“任务”“批改结果”等词；`pending/running/succeeded/failed/dead` 仅用于接口、日志和排错，界面显示中文状态。
- 错误文案说明用户可采取的下一步，不显示堆栈、SQL、令牌或内部服务地址。
- 布局支持窄屏；表格可读、长文本换行、主要操作不依赖悬停。表单标签与错误提示关联到对应控件。
- 验收：教师与学生分别走完允许的流程；加载、空、成功、失败状态均有可观察界面；学生响应和页面中找不到参考答案、评分规程或其他学生数据。
