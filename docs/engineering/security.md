# 安全开发规范

## 身份与逐资源授权

- 认证后只从服务端加载的用户记录读取 `user_id`、`role`、`class_id`。请求体、查询参数、路径附带的身份或班级值不能覆盖会话身份。
- 每个读取、下载、更新和删除端点都按具体资源验证归属；查询条件同时包含资源标识及所有者/班级。跨班、他人资源与不存在资源统一返回 404，避免泄露资源存在性。
- 教师写操作逐端点检查教师角色；学生调用教师写接口返回 403。不能以隐藏按钮代替服务端授权。
- 作业任务查询按用户/班级过滤：学生只读自己的提交和结果，教师只读本班任务。向量检索、MCP 审计和下载同样按班级/用户范围检查。
- 附件只能经完成身份与业务归属检查的下载路由读取；上传目录不得作为公开静态目录，不能提供只凭文件名或对象 ID 读取的通用接口。

## 输入、输出与密钥

- 对 JSON、表单、文件名、URL、模型输出和 MCP 返回值都按不可信数据处理；验证类型、长度、允许值和数值范围。SQL 使用参数绑定。
- HTML 模板依赖自动转义；浏览器脚本用 `textContent`、文本节点和安全属性写动态值。禁止将用户、模型或 MCP 文本拼接进 `innerHTML`，也不对其使用模板 `safe` 标记。
- 批改结果先校验 JSON 结构、分数为有限数值且在作业范围内、反馈长度受限；无效输出不得写入结果表。
- 密码只保存 Werkzeug 哈希。`SECRET_KEY`、网关 key、MCP token 及队列凭据只从服务端环境注入；不得提交到 Git、镜像、前端、API 响应或日志。
- 错误和审计摘要需脱敏；不记录 Authorization、Cookie、完整密钥、完整学生正文或完整模型/MCP 对话。

## 当前验收

- 当前代码已有服务端会话/Bearer 身份解析、密码哈希及部分跨班资源检查；新增接口仍须逐资源执行以上判据，不能据此推断所有旧端点已完成安全审计。
- 第 9、10 课加入同源校验、表单单次 CSRF token、提示指令拦截和审计回查。每次修改运行 `make check-security`，并核对[安全修复记录](../../reports/security-fix-log.md)。显式指令规则只覆盖已测模式，模型输出和工具写入仍逐资源鉴权。
