# 测试规范

## 用例来源与运行

- 用例来自正式 OpenSpec Scenario、已修复缺陷和接口边界；按正常路径、失败路径、边界三类组织。每例写清身份/数据前置条件、操作和可观察结果。
- Python 服务端测试使用 pytest、Flask test client 和临时 SQLite。用例不得读写开发库、CLab 数据卷、真实学生资料或共享 Qdrant 集合。
- 本地自动化入口为 `python -m pytest -q`。失败即阻断；不得只用人工页面点击替代自动回归。
- 纯函数和校验逻辑写单元测试；路由用 Flask test client 验证身份、状态码与 JSON schema；数据库写入和迁移用事务测试验证提交、回滚与重复调用。
- 外部服务替身只验证调用边界与失败处理。RabbitMQ 持久化、发布确认、重投和停机恢复必须另有真实 RabbitMQ 验收；替身通过不能记作真实队列通过。
- 测试记录明确区分本地替身、真实服务、跳过原因和待复验项目；不伪造网关、RabbitMQ 或同伴验证结果。

## 必测覆盖

- 身份矩阵覆盖教师、学生、未登录、跨班、他人资源和不存在资源；断言状态码、响应字段及数据库无越权副作用。
- 输入覆盖缺字段、错误类型、超长正文、非法枚举、越界分数、错误/重复幂等键；断言明确拒绝且数据未部分写入。
- SQLite 事务注入失败覆盖提交、任务、outbox 任一写入失败；断言整体回滚，无孤儿记录。
- 异步任务覆盖正常成功、轮询只读、暂时故障重试、永久故障、达到上限转 dead、死信保留原因、过期租约恢复、重复投递只产生一条结果。
- 浏览器输出测试覆盖恶意 HTML 文本以纯文本显示；结果 JSON 测试覆盖布尔分数、NaN/Infinity、超范围分数及超长反馈。
- 回归保留现有认证、资料归属、检索班级过滤、MCP 鉴权和现有会话行为。

## 通过判定

- 每条 OpenSpec Requirement 至少关联一个可重复运行的测试；任务清单中的验证方法能定位到测试名或运行命令。
- 三条第 8 课判据分别验证 20 次提交 P95、停消费者后恢复、重复提交/投递结果唯一；本地模拟与真实 RabbitMQ 结果分开记录。
- 测试失败不能用放宽断言、吞异常或跳过必要用例处理。新失败先判断产品缺陷、测试数据错误或依赖不可用，并记录证据。
